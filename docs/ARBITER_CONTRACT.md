## Why this is a pointer

The contract's own header names this repository among the four it applies to —
"RealityEngine_CPP, RealityEngine_LSP, RealityEngine_Scala, RealityEngine_Manager
(TypeScript PE)" — and records the TypeScript Perception Engine as one of the
four runtimes that implement §6 observability. This repository is bound by the
contract; it does not define it.

The master carried no pointer here until now — the failure one step before
drift. Nothing in this repository named the contract, so a reader working on the
TypeScript PE had no local sign that the rules it implements are written down
elsewhere, and the natural repair for that is a local description that becomes a
second master.

§7's parallelism directive for this runtime is the one most likely to be
rewritten locally, because it is the one that depends on a host detail: `Promise.all`
over cell shards, with `worker_threads` for the resolve when the contended set is
large, since the Node event loop will not otherwise overlap a CPU-bound
reduction. That reasoning belongs in the master with the other three, where it
can be compared against them.
